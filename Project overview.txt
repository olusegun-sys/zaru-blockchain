## Project Vision & Purpose

**ZARU** is a cryptocurrency designed for the real world, with a focus on African markets. The name combines "ZAR" (South African Rand) + "U" (You) — symbolizing African digital currency for the people.

**Tagline:** *"Digital money for the real world."*

**Core Goal:** A spendable, convertible cryptocurrency that bridges the gap between crypto and everyday life, particularly for Nigerian and African users.

## The Satoshi-Inspired Blueprint

We applied Satoshi's unorthodox thinking by arranging existing components into a novel system:

| Component | Implementation |
|:---|:---|
| Digital Signatures | ECDSA (secp256k1) key pairs for wallets |
| Timestamping | SHA-256 hashed blocks with Unix timestamps |
| Proof of Work | PoW with difficulty adjustment |
| P2P Network | TCP/IP gossip protocol |
| UTXO Model | Bitcoin-style unspent transaction outputs |

## Key Roadblocks & Solutions

### 1. Windows Compatibility

| Problem | Solution |
|:---|:---|
| RocksDB won't compile on Windows | SQLite for development, PostgreSQL for production |
| `touch` command not found | Use `echo. > file.py` or Notepad |
| Path issues | Use forward slashes or Windows paths |
| Virtual env activation | `.venv\Scripts\activate` (not `source`) |
| `cat` command not available | Use Notepad or PowerShell |

### 2. Python Dependencies

| Problem | Solution |
|:---|:---|
| `hashlib` not pip-installable | Removed from requirements (built-in) |
| `pydantic_settings` missing | Use dotenv + pydantic directly |
| `python-rocksdb` build fails | SQLite for Windows, optional for Linux |
| `cryptography` failed on first install | Install separately with pip |
| `pydantic-core` Rust compilation | Updated to Python 3.12, pre-compiled wheels |

### 3. Pydantic V2 Migration

| Problem | Solution |
|:---|:---|
| `class Config` deprecated | Use `model_config = {}` instead |
| `@dataclass(order=True)` conflict | Remove `order=True`, manual `__lt__` |

### 4. Dataclass Issues

| Problem | Solution |
|:---|:---|
| `field` not defined in protocol.py | Added `from dataclasses import dataclass, field` |
| `__lt__` conflict with `order=True` | Removed `order=True`, kept manual `__lt__` |

### 5. Render Deployment

| Problem | Solution |
|:---|:---|
| `$PORT` parse error | `_get_api_port()` function to handle Render's PORT |
| `ZARU_API_PORT` env var | Let code use `PORT` automatically |
| No open ports detected | Fixed config.py import errors |
| CORS blocking wallet | Added explicit CORS middleware with `allow_origins=["*"]` |
| Syntax errors in miner.py | Removed accidental comments inside Python files |
| Mining reward not credited | Added coinbase transaction to `mine_test_block()` |

### 6. Wallet Deployment

| Problem | Solution |
|:---|:---|
| Blank page (Render Web Service) | Changed to Static Site |
| Blank page (Vercel) | Added `vercel.json` for static config |
| JavaScript syntax errors | Removed arrow functions, used `function()` syntax |
| Missing JavaScript functions | Added `call()`, `load()`, `refreshBalance()`, etc. |
| CORS blocking API calls | Added CORS middleware to API |

### 7. File Writing Issues (Windows)

| Problem | Solution |
|:---|:---|
| `cat` command not available | Use Notepad or PowerShell |
| Long files not saving | Use PowerShell to write files |
| Echo command truncating content | Use Notepad or PowerShell |
| File corruption | Use clean Notepad save with "All Files" type |

## Architecture Decisions Recorded

### Why UTXO Instead of Account Model?

| UTXO Model | Account Model |
|:---|:---|
| Privacy (new address per tx) | Less privacy |
| Parallel validation | Sequential validation |
| Bitcoin-style | Ethereum-style |
| Better for scaling | Easier for developers |

### Why SQLite First?

- ✅ Works on Windows (no compilation)
- ✅ Built into Python
- ✅ Good for development/testing
- ✅ Easy to migrate to PostgreSQL

### Why PostgreSQL for Production?

- ✅ Concurrent connections
- ✅ Better performance at scale
- ✅ JSONB support
- ✅ Render.com native support

### Why Disable P2P Network on Render?

- ✅ Reduces log noise
- ✅ Prevents port binding issues
- ✅ API-only mode is sufficient for initial deployment

### Why CORS Allowed All Origins?

- ✅ Simplest solution for wallet access
- ✅ Development mode
- ✅ Can restrict later with `ENABLE_CORS=true`
